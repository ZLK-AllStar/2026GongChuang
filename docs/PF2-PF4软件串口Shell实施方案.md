# PF2/PF4 软件串口 Shell 实施方案

> 日期：2026-11-02（Asia/Shanghai）。状态：方案已编写，固件未实施，编译、模拟和实机验收均未执行。
>
> 背景：用户反馈 Shell 所用 UART5 硬件线路断路，拟使用 PF2/PF4 和 TIM13 实现 4800 baud、8N1 软件串口。本方案基于当前工作区源码核查和时序计算，不代表已经验证引脚导通、外部接线或通信稳定性。

## 1. 目标与边界

将 DEBUG 模式下 Letter Shell 的物理收发后端从 UART5 迁移到软件串口，保留命令、回显、行编辑、错误统计和机械动作期间的输入保护。结论为有条件可行，放行条件见第 9 节。

| 项目 | 实施规格 |
|---|---|
| MCU | STM32F407ZGT6，现有 168 MHz 系统时钟 |
| TX | PF2，推挽输出，空闲高电平 |
| RX | PF4，上拉输入，空闲高电平 |
| 串口 | 4800 baud、8 数据位、无校验、1 停止位，LSB first，无流控 |
| 双工 | TX/RX 独立状态机，共用 TIM13 固定节拍，支持同时收发 |
| 定时器 | TIM13，8 倍采样，约 38.4 kHz 更新中断 |
| 模式 | 仅 DEBUG 初始化并启动；HOST 不启动软件串口 |
| 时基 | 保留 SysTick/HAL_GetTick，不把 TIM13 改成应用毫秒时基 |

PF2=TX、PF4=RX 是本方案选定的实施分配，尚未通过实际接线确认。

实施约束：

1. 不手工修改 `.ioc`，不运行 CubeMX 重生成。GPIO/定时器运行时重配放在应用模块或生成文件的 `USER CODE` 区。
2. 保持 ARMCC 5.06 update 7 build 960、target `HUATAI`、现有启动文件与 HAL 基础初始化。
3. 保留 USART1 电机协议及 DMA+IDLE 架构、USART2 HOST 协议、USART3 HMI、TIM1/TIM3 PWM 和机械动作语义。
4. 不在中断或等待服务钩子中解析 Shell，不由软件串口引入机械动作重入。
5. 本次实施不提供同步机械动作中的即时软件急停；忙碌期间收到的命令继续丢弃。
6. 以当前工作区文件为实施基线，保留已有未提交修改。历史机械方案中的 UART5/TIM13 描述是旧基线；本方案实施后需同步更新当前使用说明。

## 2. 已核查的代码基线

| 资源/行为 | 当前状态与证据 | 对实施的影响 |
|---|---|---|
| PF2/PF4 | `Core/Src/gpio.c`、`board_io.c`、`tim.c`、`usart.c` 未见应用占用；GPIOF 当前用于 PF9/PF10 LED 和 PF12 屏幕 DC | 软件层面可分配，仍需核查板上连接 |
| 外部 SRAM | `ext_sram.c` 使用内部 SRAM；`system_stm32f4xx.c` 的 `DATA_IN_ExtSRAM` 未启用，Keil 宏也未启用它 | 当前无已启用 FSMC 地址总线占用；不得因文件名误判 |
| 时钟 | `main.c::SystemClock_Config()` 使用 HSI→PLL，HCLK=168 MHz、APB1=42 MHz，APB1 定时器时钟=84 MHz | TIM13 参数按 84 MHz 计算，不能按 42 MHz 计算 |
| TIM13 | `MX_TIM13_Init()` 已调用，PSC=0、ARR=65535；未见应用启动 | 可在 DEBUG 初始化时重配并启动 |
| 共享 IRQ | `stm32f4xx_it.c::TIM8_UP_TIM13_IRQHandler()` 已调用 TIM8、TIM13 HAL handler | 必须按来源处理，不能误清 TIM8 标志或重复推进状态机 |
| 中断优先级 | TIM8/TIM13、USART1、DMA2 Stream2/7 当前均为抢占优先级 0 | 同级不能互相抢占，需测量并处理延迟 |
| 关中断区 | `usart.c::UART_RxPopFrame()` 在全局关中断期间复制数据，`CMD_LEN=255`；Shell/HostLink 也有短临界区 | 不能仅根据平均 CPU 占用判定可靠性 |
| Shell TX | `shell_port.c::Write()` 使用 `HAL_UART_Transmit(&huart5, ..., 100U)` | 替换后端并重算超时 |
| Shell RX | UART5 单字节 IT；RX 环 256 字节，编辑缓冲 512 字节 | 可复用行处理，需解除对 UART5 私有接收字节的依赖 |
| 全局 UART 回调 | `host_link.c` 按 Instance 分发 UART5 的完成与错误回调 | 切换后避免 UART5 再向 Shell 注入数据 |
| 屏幕与等待 | `screen.c` 阻塞 SPI 发送；`app_runtime.c` 服务显示/HOST；SysTick 只更新 tick | 主循环阻塞不等于关中断，收发位时序必须独立于主循环 |
| PWM | TIM1/TIM3 硬件 PWM，TIM8 当前未启动应用输出/更新中断 | 不直接争用 TIM13，但共享 IRQ 仍需兼容 |

本表是源码层面的核查；未读取目标板寄存器，未测量中断耗时或引脚波形。

## 3. 硬件接线与启动电平

| 板端 | USB-TTL 转接器端 |
|---|---|
| PF2 / TX | RXD |
| PF4 / RX | TXD |
| GND | GND |

使用 3.3 V TTL 电平，不直接连接 RS-232 正负电压接口。终端配置为 4800、8N1、无流控；优先关闭终端本地回显，使用固件回显。

上电前核实 PF2/PF4 到连接器的导通情况、是否与其他板载器件连接、是否存在短路或外部输出争用。需要在复位期间维持稳定空闲电平时，可按板上负载评估外加上拉。

初始化顺序：使能 GPIOF 时钟，先将 PF2 输出锁存位置高，再配置为推挽输出；PF4 配置上拉输入。使用 `BSRR` 更新 PF2，禁止对整个 GPIOF 的 ODR 做无保护读改写，避免影响 LED/屏幕引脚。

不需要将 PF2/PF4 复用成定时器通道；TIM13 只提供 CPU 中断节拍。推荐方案不使用 EXTI，避免增加起始沿与周期定时器的协调逻辑。

## 4. 定时参数与状态机

### 4.1 固定 8 倍节拍

```text
目标位时间       = 1 / 4800 ≈ 208.333 μs
8N1 帧时间       = 10 / 4800 ≈ 2.083 ms
每方向理论吞吐量 = 480 字节/秒

TIM13 输入时钟   = 84 MHz
PSC             = 0
ARR             = 2187
更新频率         = 84,000,000 / ((PSC + 1) × (ARR + 1))
                 ≈ 38,391.225 Hz
节拍周期         ≈ 26.048 μs
实际位时间       = 8 × 节拍周期 ≈ 208.381 μs
实际波特率       ≈ 4798.903 baud
分频误差         ≈ -0.0229%
```

分频误差很小，但不是完整时钟误差：当前时钟来自 HSI，需叠加 HSI 漂移、对端波特率误差、起始沿量化和中断抖动。降低波特率增加绝对时间裕量，不会自动消除相对时钟误差。

初始化时停止计数/更新中断，配置 PSC/ARR/CNT，产生更新事件使预分频配置生效，清理本外设更新标志，设置状态机，再开启更新中断和计数。共享 NVIC pending 的处理不得误吞 TIM8 待处理事件。

### 4.2 接收状态机

1. `WAIT_IDLE`：启动或帧错误后，确认线路恢复高电平；持续低电平不得反复产出 `0x00`。
2. `IDLE`：每节拍读 PF4，检测到低电平后建立本帧相位。
3. `START`：约半位（4 个节拍）后再次确认低电平；若为高，则作为假起始位退出。
4. `DATA`：从起始位确认点再等待 8 个节拍采样 D0，然后每 8 个节拍采样下一位，按 LSB first 组装 8 位数据。
5. `STOP`：再等待 8 个节拍检查停止位。为高时交付一个完整字节；为低时计帧错误、标记输入行损坏并等待恢复。
6. 正常停止位采样后即可恢复起始检测，不能额外等待完整空闲位，否则会漏掉无间隔连续字节。

从检测到起始低电平起，D0 约在第 12 个节拍、停止位约在第 76 个节拍采样。实现与测试必须统一计数定义，避免多算/少算一个节拍。8 倍采样引入最多约一个采样周期的起始检测量化误差，应纳入接收裕量。

帧错误、采样失步和 RX 溢出均不得让残缺命令继续执行。持续低电平按一次故障段处理，恢复高电平后才重新接收。

### 4.3 发送状态机

TX 队列非空时，在定时节拍边界取一个字节，输出低电平起始位；每 8 个节拍切换至下一位，发送 D0～D7，再保持高电平停止位满 8 个节拍。之后可立即开始下一帧，空队列时持续保持高电平。

RX 检测不得重置 TIM13 CNT 或 TX 相位；TX 启停也不得重置 RX 相位。每次 IRQ 同时推进两个独立状态机，以保证全双工。

## 5. 中断时延与 CPU 预算

以完整 IRQ 路径计时，包含异常进入/退出、共享向量处理、GPIO 读写、状态机及字节交付。若每次为 1 μs，CPU 占用约 3.84%；若为 2 μs，约 7.68%。这些是预算示例，不是实测结果。

实施原则：

- ISR 不调用 Shell、格式化打印、HAL_Delay、SPI 刷新、机械控制或阻塞串口函数；不在 ISR 中等待队列空间。
- 优先使用 GPIO IDR/BSRR 和短状态机。可在已有共享 IRQ 的 `USER CODE` 区增加 TIM13 快速分支，检查 UIF/UIE 后仅清除 TIM13 更新标志。原 HAL 路径不得再次推进同一节拍。
- 若采用 `HAL_TIM_PeriodElapsedCallback()` 接入，必须按 `htim->Instance` 分发，并测量包括两个 HAL handler 在内的完整开销；两种接入方式选一种。
- 初始设计目标：从定时事件到实际 GPIO 采样/输出的最坏延迟尽量不超过 10 μs，完整 ISR 预算尽量控制在 2 μs 左右。它们是测量目标，不是已经证明的硬性能力。
- 对 `UART_RxPopFrame()`、USART1 IDLE ISR、DMA IRQ 及其他全局关中断区进行最坏耗时测量。不能把 255 字节复制假定为零成本，也不能用缩短正常电机帧代替异常满帧测试。
- 如同级中断阻塞过长，可评估 TIM13 保持优先级 0，USART1/DMA 改为较低抢占优先级；实施前核查 UART/DMA HAL 并发关系，并回归电机通信。不未经验证统一调整全局优先级。
- 提高中断优先级无法绕过 PRIMASK。确需缩短全局临界区时，重新设计队列索引发布/复制所有权，不能简单把复制移出锁后留下 ISR 覆盖竞态。

固定节拍状态机依赖不丢节拍；更新标志不是可累计的事件队列。若中断屏蔽超过一个周期，不应连续“补跑”状态机冒充真实采样。实现时应评估用独立运行的计数源（如 DWT CYCCNT）检测超预算间隔，发生失步时计错并废弃当前接收行；发送帧无法撤回，需记发送故障并恢复稳定空闲，不能宣称已可靠发送。检测计数源须处理回绕，且不能取代实测时序保证。

## 6. Shell 适配、缓存和并发

### 6.1 模块边界

建议新增 `Core/Inc/soft_uart.h`、`Core/Src/soft_uart.c`，负责 GPIO、TIM13、TX 队列、收发位状态机和底层诊断。完成字节直接交付 Shell 的短入队接口，避免再添加一套功能重复的 RX 环。

建议接口（名称可按实现细化）：

| 接口 | 调用上下文/职责 |
|---|---|
| `SoftUart_Init()` | 主循环上下文，初始化后端并报告成功/失败 |
| `SoftUart_TickFromISR()` | TIM13 IRQ，仅执行一个定时节拍 |
| `SoftUart_Write()` | 主循环上下文，复制数据入 TX 队列，满时有限等待 |
| `SoftUart_GetDiagnostics()` | 获取收发计数、帧错误、失步及 TX 超时统计 |
| `ShellPort_RxByteFromISR(byte)` | 完整字节进入现有 RX 环，执行 busy/溢出保护 |
| `ShellPort_RxErrorFromISR()` | 标记输入行损坏，不在 ISR 打印错误 |

`ShellPort_Init()` 必须先准备 RX 状态、配置 `console.write` 并启动可用的软件 TX 后端，再调用可能打印欢迎信息/提示符的 `shellInit()`。在 Shell 对象完全就绪前可暂不接纳 RX 字节。防止启动打印等待尚未启动的 TIM13 而死锁。

### 6.2 配置集中管理

GPIO、波特率、过采样倍数、缓存与超时参数集中于 `app_config.h`。建议新增 `APP_SHELL_SOFT_UART_*` 宏族，具体命名保持一致。

| 参数 | 初始建议 | 说明 |
|---|---|---|
| 波特率/过采样 | 4800 / 8 | 从时钟与配置推导 PSC/ARR，或校验固定参数的前提 |
| TX 环 | 512 字节 | 初值，非已验证容量；一空槽方案可用 511 字节 |
| RX 环 | 先保留 256 字节 | 一空槽方案可用 255 字节 |
| 编辑缓冲 | 保留 512 字节 | 不等于 RX 可缓存 512 字节 |
| 发送超时余量 | 按入队量、已排队量和主循环服务耗时计算 | 禁止继续固定使用 100 ms |

增加缓存前检查 Keil 链接后的 RAM/ZI、栈余量及现有 76800 字节帧缓冲。512 字节 TX 环只是初始建议，不以无限加大缓存掩盖持续生产速度超过线速的问题。

### 6.3 发送与背压

100 字节在 4800 下需要约 208 ms，1 KiB 约 2.13 秒。`Write()` 必须复制调用者数据到 TX 环，不能保存 `shellPrint()` 栈缓冲指针后立即返回。

正常返回值表示已接受的字节数，不表示已经到达对端。TX 环满时在主循环等待空间，可调用既有 `AppRuntime_Service()` 保持显示/HOST 服务，但不得调用 `ShellPort_Poll()`、`shellHandler()` 或开始机械动作。等待期间中断必须打开；禁止从 ISR 调用该发送接口。

超时按最坏待发送字节数估算：`ceil((待处理字节数 × 10 × 1000) / 实际波特率)`，另加有依据的调度余量；使用足够宽的整数避免溢出。TX 关中断区仅用于必要的短状态发布，不能覆盖整段字符串复制或等待。

队列满是正常背压，不能静默丢弃。真正超时时记录发送错误并返回实际接受长度；Letter Shell 的调用点并非都会重试短写，需验证错误传播和恢复行为。不得在 TX 故障路径递归调用同一 `Write()` 打印报错。

### 6.4 输入完整性与 busy 边界

保留 `busy`、`line_open`、`damaged`、`discard_line` 的保护语义。帧错误、溢出或失步发生时，清空受影响的编辑内容并要求换行后重输；带错误的半条命令绝不能触发机械动作。

软件串口一帧持续约 2.08 ms，不能只在停止位完成时检查 busy：一帧可能在动作期间开始、在动作结束后才完成。实施时需给接收中的帧记录 busy/输入代际信息，或使用等价方案，使跨 busy 边界的帧及其残余输入行继续被丢弃。`ShellPort_EndAction()` 除清 RX 环，还需与在途接收状态协调；不要为了清 RX 状态重置公共定时器而破坏 TX。

255 字节 RX 有效容量仅能容纳约 0.53 秒连续满速输入。长 `help` 输出、行编辑回显或连续粘贴可能使主循环来不及消费 RX。人工调试按“提示符出现后发送一条命令”操作；测试必须覆盖溢出后恢复，不能宣称支持无限速批量粘贴。若后续要求可靠批量脚本，应另行设计流控/确认机制。

## 8. 实施顺序

1. 保存工作区状态与现有回归结果，确认板上 PF2/PF4 可用；记录当前编译器、时钟和 RAM 使用。
2. 实现独立的软件串口状态机与配置，先验证虚拟 GPIO/节拍下的协议，不接机械命令执行。
3. 接入 TIM13 和 GPIO，检查初始化空闲电平、稳定节拍及共享 IRQ 行为。
4. 替换 Shell 后端，处理初始化打印顺序、TX 数据生命周期、RX 错误和 busy 跨帧问题。
5. 完成离线回归与 Keil 全量重建；按下节测试矩阵进行实机收发和并发时序测试。
6. 根据实测延迟决定是否需要中断优先级/临界区优化，修改后重跑对应电机与串口测试。
7. 更新使用说明及验证记录，填写真实结果；未完成项继续标记“未验证”。

## 9. 验证与放行标准

### 9.1 离线测试和编译

新增有实际输入/输出断言的状态机测试，至少覆盖：

- 全部 256 个字节值的 TX 位序和 RX 解码；起始/停止位宽度。
- RX 起始沿相对于采样节拍的不同相位；无间隔连续帧及全双工。
- 假起始位、停止位低、持续低电平、恢复高电平、输入失步与计时回绕。
- TX/RX 环回绕、队列满、TX 超时、临时发送缓冲在返回后被覆盖。
- busy 开始/结束发生于起始位、数据位、停止位期间；动作完成后残余命令不能执行。
- 接收损坏/溢出时丢整行、换行后恢复；长输出不会引发 Shell 重入。
- HOST 不启动 TIM13 软件串口；TIM8 事件不被误处理；一个 TIM13 事件只推进一次。

### 9.2 实机测试矩阵

| 测试 | 方法 | 放行条件 |
|---|---|---|
| 电气与启动 | 测量供电、PF2/PF4 导通和空闲电平；复位观察 TX | 3.3 V TTL 接线正确，无输出争用，无伪起始长低电平 |

| 假起始/断线 | 注入窄脉冲、错误停止位、持续拉低，再恢复 | 错误可统计，不生成可执行残缺命令，可恢复 |
| Shell 交互 | 输入、退格、历史、补全、help/status 长输出 | 回显和命令正确；长输出不因旧 100 ms 超时截断 |
| 输入过载 | 长输出期间连续粘贴超过 RX 环容量 | 整行丢弃并提示恢复，不执行拼接命令 |
| busy 边界 | 在动作开始/结束附近连续输入，覆盖在途字节 | 不将动作期间的残余输入解释为新机械命令 |
| 并发负载 | 屏幕刷新、电机应答/DMA、Shell 收发同时运行 | 无采样失步；记录最大中断延迟、完整 ISR 耗时及 CPU 占用 |
| 电机回归 | 验证 XY/托盘正常应答及异常帧/超时路径 | 无新增通信错误或机械行为改变 |
| 模式隔离 | DEBUG/HOST 分别启动 | DEBUG 可用；HOST 无软件串口定时中断负载，原协议与按钮行为正常 |

连续原始字节测试通过独立测试入口进行，不能把随机二进制流直接交给可执行机械命令的生产 Shell。每方向 100000 字节至少约需 208 秒；测试记录实际持续时间、数据量和误码情况。

如无法直接观测内部定时事件，可使用经核实空闲的测试引脚、调试计数或独立硬件参考测量 IRQ 延迟；不能仅观察 ISR 内翻转的 GPIO 脉宽，就宣称已测得中断到达前的等待延迟。测量插桩开销需要计入或单独校准。

满足正常负载下无丢节拍/无通信错误、异常输入安全恢复、现有功能回归通过后，才标记“可用于实机 DEBUG Shell”。主机模拟通过不能替代线路、电平、HSI 漂移和最坏中断延迟验收。
